# CHANGES-20260924

## 2026-09-24 09:14:00 (GMT+8)

- **原生系统文件夹/文件选择对话框穿透置顶（解决“点浏览无反应”）**：
  - 根因排查：在 Windows 10 环境下，从 Node.js 调起 PowerShell 的 `FolderBrowserDialog` / `OpenFileDialog` 若未提供所有者窗口（Owner Window Handle），操作系统默认将弹窗置于底层，在浏览器或 Edge App 全屏/前台时被遮挡在背后无法被视觉察觉，表现为“点击无反应”。
  - 核心修复：
    - `ffweb/dialog.js` 中创建隐藏的 `$form = New-Object Windows.Forms.Form; $form.TopMost = $true; $form.Activate(); $form.BringToFront();` 并将其作为 Owner 传入 `ShowDialog($form)`，强制对话框突破层级穿透置顶于浏览器正前方；
    - 改用 UTF-16LE 转 Base64 的 `-EncodedCommand` 参数调用 PowerShell，彻底杜绝命令行多行换行、引号和中文路径转义解析失效的问题；
    - 补齐异常日志记录，防止错误被静默吞没。
  - 前端反馈增强：
    - `ffweb/assets/app.js` 为「选择文件」、「浏览目录」和「输出目录」按钮添加点击时的 `⏳ 打开中...` 禁用加载中状态与交互反馈，并在发生异常时弹出友好的错误提示。

## 2026-09-24 09:03:00 (GMT+8)

- **流级元数据保护与多轨语言/标题完整保留**：
  - 根除预设 `streamArgs` 中有害的 `-map_metadata:s:v 0:s:v` 与 `-map_metadata:s:a 0:s:a`，统一改为全局 `-map_metadata 0`；并在 `buildStreamArgs` 中加入防御性正则过滤。
  - 恢复 FFmpeg 默认的 per-stream 元数据流映射机制，解决此前显式指定单个流元数据导致所有其它音频轨和字幕轨的语言代码 (`lang` / `language`) 与标题 (`title`) 被彻底丢弃的问题。
- **清除重编码流过期统计标签（根治 MediaInfo 虚高码率）**：
  - 在 `buildMetaArgs` 中对重编码的视频轨与音频轨显式清空 MKV/mkvmerge 遗留的旧统计标签：`BPS=`、`NUMBER_OF_BYTES=`、`NUMBER_OF_FRAMES=`、`_STATISTICS_TAGS=`、`_STATISTICS_WRITING_APP=`、`_STATISTICS_WRITING_DATE_UTC=`。
  - 彻底解决转码产物在 MediaInfo 中依然读取源视频旧的 `BPS=9386897` 导致显示 9000+ kbps 的问题，使播放器与分析工具准确显示实际转码码率。
- **WebUI 日志镜像落盘与即时 Flush**：
  - `ffweb/task_runner.js` 将所有 WebUI 日志通过 `log.fileLog` 同步写入会话文本日志文件；
  - 在任务批次完成、单任务结束、中止及 WebServer 关闭时显式调用 `log.flushFileLog()`，保证日志即时落盘至操作系统临时目录（`%TEMP%\mediac`）。
- **自动化测试补充**：
  - 在 `test/test_ffmpeg_params_v2.js` 中新增针对流元数据保护、BPS 清理以及 streamArgs 过滤的自动化单测，全绿通过。

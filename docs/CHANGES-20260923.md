# CHANGES 2026-09-23

## 分辨率码率缩放改为像素面积幂律 α=0.75（15:50）

- **`ffmpeg_plan.calculateDstArgs` 重构 `scaleBitrateByResolution`**：丢弃旧的「长边线性比 + 1.1 系数」与「<1080p 面积再缩放 + smoothChange 0.3」两段拼接，收敛为单条幂律：`scale = (dstPixels / anchorPixels) ^ 0.75`。
- **锚点 = 预设名义像素**：`anchorPixels` 取"源按目标长边 `dstDimension` 等比缩放的理论尺寸"（不受 `calculateScale` 禁止放大限制），使预设自身档位恰为满分 1.0、不缩放；实际输出低于预设档位时（如 4K 预设压 1080p）按像素比幂律下降码率。
- **α=0.75（感知非线性）**：4K 本就比 1080p 清晰很多，分辨率放大时码率不必同比放大；反之分辨率压低也不削太狠。`dstVideoBitrate`/`dstMaxBitrate` 共用同一缩放，峰值上限与平均码率同比例变化。
- **移除魔法**：删除 `pixelsScale`、`×1.1`、`smoothChange`、`PIXELS_1080P` 阈值分支、`bigSideDst`；日志改打 `dstPixels`/`anchorPixels`/`powScale`。
- **测试**：新增 `calculateDstArgs` 3 例（档位一致满分 1.0 / 4K 预设压 1080p→0.25^0.75 / maxBitrate 同比例缩放且保持 ×1.5）；`npm run check` 通过、ffmpeg 相关 4 个测试文件 **120/120 通过**、改动文件 lint 干净。

## 预设码率统一为严格字符串（15:10）

- **YAML 预设 `videoBitrate`/`audioBitrate`/`maxBitrate` 改为严格字符串带单位**（如 `4M`、`233k`、`1.6M`），与 CLI `--video-bitrate` 同款语法、同一 `parseBitrate()`（1000 进制）——消灭 preset 里数零/单位不一致的历史痛点。
- **转换收敛在构造器**：`FFmpegPreset` 新增 `normalizeBitrate()`，对 string 经 `parseBitrate` 归一为 bps 数字、对裸数字原样接受（程序化构造/测试向后兼容）。内部 `dstVideoBitrate`/`dstMaxBitrate`、探测链等全部保持 bps 纯数字，零改动。
- **schema 严格化**：`preset_schema.js` 三个码率字段 `type` 由 `number` 改 `string`，YAML 里出现纯数字会被 `hasPresetTypeMismatch` 置灰忽略（提示写带单位字符串）。
- **default.yaml 全量迁移**：26 处 `videoBitrate` + 36 处 `audioBitrate` 数值改为带单位字符串（含 800k/1.6M/1.2M 等）；顶部注释补充码率写法规约。
- **YAML 引号**：`4M`/`192k` 等带单位写法裸写即可、无需引号（非数字字面量）；只有想强制当字符串时才加引号（裸数字必须引）。
- **测试**：新增 `FFmpegPreset bitrate normalization` 3 例（字符串→bps / 裸数字兼容 / 未设归 0）；preset 相关 4 个测试文件 **117/117 通过**；`npm run check` 通过。

## 预设支持显式 maxBitrate（峰值码率）（14:30）

- **预设新增 `maxBitrate`（bps）**：`preset_schema.js` 白名单 + `FFmpegPreset` 构造器接收该字段；在 `presets.yaml` 中声明即作为 `-maxrate` 峰值上限。
- **随分辨率 scale（与 videoBitrate 同规则）**：`ffmpeg_plan.calculateDstArgs` 将分辨率缩放提取为 `scaleBitrateByResolution()` 助手（长边比例 scale + 1080p 以下按像素密度再缩放），`dstVideoBitrate` 与新增 `dstMaxBitrate` 共用同一缩放；`dstMaxBitrate` 只在显式声明时计算。
- **buildEncoderArgs 缺省兜底**：`lib/hwaccel.js` 的 VBR 分支 `-maxrate` 改为——`maxBitrate > 0` 直接用（已 scale 过的 bps），否则保持既有 `bitrate × 1.5`。
- **透传链路**：`ffmpeg_build.buildVideoArgsFromPlan` 与探测链 `selectTier`/`probeLayer`/`buildLayerArgs`/`buildProbeArgs` 全程透传 `maxBitrate`，保探测=真实同构；`ffmpeg_run.resolveHwPlan` 传 `entry.dstArgs.dstMaxBitrate`。
- **测试**：`test_ffmpeg_t5_hw_autofit.js` 新增 2 例（显式 maxBitrate 覆盖 ×1.5 / falsy 时保持 ×1.5）；ffmpeg 相关 3 个测试文件 **90/90 通过**；`npm run check` 通过。

- **ffmpeg 编码器参数块（`buildEncoderArgs`）重构**：`lib/hwaccel.js` 的 switch 现统一按「有无目标码率」分发两种码控模式——有 `bitrateK` 走 VBR（`-b:v` 系）模式，无则走 CQ（恒定质量）模式；各编码器采用各自正确的质量参数名（nvenc `-cq`、qsv `-global_quality`、amf `-qvbr_quality_level`、其余 `-crf`）。全部参数按本机 N-126733 真机 `ffmpeg -h encoder=X` 与 `data/videos` 测试源实测核准。
- **补齐 AMF 码控参数**：AMD 分支不再仅发 `-b:v`，补上 `-rc qvbr` + `-qvbr_quality_level`（CQ）与 `-rc vbr_peak`（VBR），选项名经 `-h encoder=hxxx_amf` 确认存在；无 A 卡仍待实拍复验。
- **AGENTS.md 补充本机 ffmpeg 多版本环境**：注明 `C:\Home\Apps\ffmpeg` 各版本（默认 `bin` 为 N-126733 master、PATH 即指向它）及测试素材 `data/videos/`。

## 码率单位统一：内部一律 bps，边界格式化（10:35）

- **结论**：内部/preset/parser 全部保持 **bps**（与 mediainfo 同源），`buildEncoderArgs` 改为接收 bps 纯数字 `bitrate`，仅拼 ffmpeg 时用 `kb()` 格式化为 `"xxxK"`（见 `docs/BITRATE-UNIT-PLAN-20260923.md` 的最终方向）。
- **`buildEncoderArgs`（`lib/hwaccel.js`）**：入参 `bitrateK`→`bitrate`（bps），新增 `maxBitrate`（bps，可选，缺省 = `bitrate × 1.5`）；VBR 分支 `-b:v kb(b) -maxrate kb(m) [-bufsize kb(m)]`（amf/svtav1 等按编码器只发 `-b:v`）。
- **透传链路统一**：`buildLayerArgs`/`probeLayer`/`selectTier` 的 `bitrate`/`maxBitrate` 全程随探测透传（探测命令与真实命令同构）。
- **取数与接参**：`ffmpeg_build.buildVideoArgsFromPlan` 改取 `tempPreset.dstVideoBitrate || tempPreset.videoBitrate`（bps）；`ffmpeg_run.resolveHwPlan` 改传 `entry.dstArgs.dstVideoBitrate`。
- **模板/展示分离**：`videoBitrateK`/`audioBitrateK` 等带 K 字符串**仅用于模板注入与展示**（audioArgs `-b:a {audioBitrateK}`、文件名后缀 `s_256K`），**不再参与码控计算**。
- **测试**：`test_ffmpeg_t5_hw_autofit.js` 相应断言改为 bps 输入 + maxrate=×1.5（`2000K`/`3000K`）；56 用例全部通过；`npm run check` 通过；cpu x264 VBR 已真机实测 EXIT=0。
- **备注**：方案文档已更新为"bps 纯数字 + 边界格式化"方向；`i18n` 里 `--video-bitrate` describe 仍写 "in kbytes"，与 bps 实现不符的历史问题保留待单独处理（不在本次范围）。

## 简化 maxBitrate + 清理（11:00）

- **去掉独立 `maxBitrate`**（`lib/hwaccel.js`）：`buildEncoderArgs`/`buildLayerArgs`/`probeLayer`/`selectTier` 不再有 `maxBitrate` 入参。峰值上限固定 `m = bitrate × 1.5`——`bitrate` 本就是 `dstVideoBitrate`（已按分辨率 scale），故 `×1.5` 天然随分辨率缩放，无需独立字段/不应缩放。

- **带 K 注释语义**：`ffmpeg_build.js`/`hwaccel.js` 注释明确——`videoBitrateK`/`audioBitrateK` 是**字符串**，仅供文件名/模板（audioArgs `-b:a {audioBitrateK}`、suffix `_{audioBitrateK}`）注入使用，不参与码率计算。
- **文档/i18n**：`FFMPEG-USAGE.md` 移除不存在的 `{bitrate}` 模板变量死链；`i18n` 的 `--video-bitrate/--audio-bitrate` describe 改为"单位 Kbps（内部 ×1000 得 bps）"。
- **测试**：ffmpeg 相关 5 个测试文件 **132/132 通过**；`node --check` 通过；真机验证 nvenc VBR `-b:v 4000K -maxrate 6000K`。

## CLI 码率参数支持字符串（233k/3M）（11:40）

- **新增 `parseBitrate(str)`**（`lib/helper.js`）：解析码率字符串为 **bps**，按 **1000 进制**（与 ffmpeg `-b:v "3M"`=3_000_000 一致；区别于文件容量的 1024 进制）。裸数字=bps，支持 `k/m/g`（大小写均可），非法输入抛 Error。

- **i18n** describe 更新为"裸数字=bps 或带 k/m/g"。
- **测试**：新增 `parseBitrate` 4 个用例（test_helper.js）；ffmpeg 相关 5 文件 + test_helper 全部通过；`node --check` 通过。

## 09:20 第六轮：P2 高危项修复

依据 `CODE-REVIEW-20260919.md` 第 3 节与第 5 节，优先处理「会挂死」「结果错误」两类。

### P2-11 `pick` 是唯一「默认就真写盘」的命令（最危险的一项）

- 其余命令（`remove`/`move`/`moveup`/`rename`/`prefix`/`zipu`/`compress`/`dcim`/`ffmpeg`）
  统一用 `--doit`（默认 false，即默认预览），唯独 `pick` 用 `--dry-run`
  且**默认 false** —— 敲 `mediac pick .` 以为在看计划，实际已经复制了几千个文件。
- 改为与其它命令一致：默认预览；`--doit` 才真复制；`--dry-run` 保留为显式预览
  （不设短别名，`-d` 已被 `--day-limit` 占用、`-n` 归 `--dry-run`）。

### 会挂死的两项

- `lib/helper.js` `fileHash` 的读取流**未监听 `error`**：文件在读取途中被移走/无权限/是目录时，
  既不触发 `data` 也不触发 `end`，Promise **永不 settle**，调用方直接卡死
  （rename/dedup 这类批量场景里文件被并发移走是常态）。补 `error` 监听，
  并把 `reject(字符串)` 改为 `reject(Error)`。
- `lib/file.js` `getDirectoryFileCount` 用 `fs.stat`（**跟随符号链接**）递归，
  目录树里出现指向祖先的链接（含 Windows junction）即无限递归至栈溢出。
  改为 `lstat` 并跳过符号链接。（`getDirectorySize` 本就用的 `lstat`，已确认安全。）

### 结果错误的四项

- `lib/media_parser.js:134` `bitDepth` 两个操作数**完全相同**
  （`bits_per_raw_sample || bits_per_raw_sample`）→ 备选字段永远取不到。改为 `bits_per_sample`。
- `lib/tools.js` `hashCache` **以路径为键、无失效机制**：文件被改写后仍返回旧哈希，
  两个已不同的文件被判为相同（DUP）而跳过移动，静默丢失处理。
  → 缓存值改为 `{hash, size, mtimeMs}`，读取时校验 size 与 mtimeMs，不一致即失效。
- `lib/core.js` `countOccurrences` / `uniqueByFields` 用 `{}` 作字典：
  键为 `__proto__` / `toString` 时会读到原型链上的对象/函数，
  前者 `+1` 得 NaN，后者被判为「已见过」而丢弃条目。→ 改用 `Object.create(null)`。
- `lib/core.js` `comparePathSmart` 的 `/\p{ASCII}/u` 只要**任一**字符为 ASCII 即命中，
  于是 `D:/照片/IMG_001.jpg` 这类中西混排路径走 `toLowerCase()` 码点比较而非
  `localeCompare`，中文排序错误。→ 改为 `/^[\p{ASCII}]+$/u`（全部字符均为 ASCII）。

### P2-7 Windows 上「仅大小写变化」的重命名被误判为冲突

- `abc.txt → ABC.txt`：字符串不相等，但大小写不敏感的文件系统上
  `fs.pathExists(newPath)` 命中的正是自己 → 被判为冲突并生成 `ABC_1.txt`，
  用户想要的大小写修正反而没生效。
- 新增 `conflictKey()`（Windows/macOS 上归一为小写）：「仅大小写变化」直接放行，
  `seenPaths` 的写入与查询也一并归一，避免批内大小写撞名漏检。

## 08:35 第五轮：P1 全项修复（依据 CODE-REVIEW-20260919.md 第 2 节）

承接第四轮（P0 全项 + 门禁重建），本轮修完剩余的 8 项 P1。
验证：`check` 79/79、`test` 49/49、`eslint` 非 prettier 项 **0 错误**、`node index.js --help` 正常。

### P1-1 `presets.yaml` 死配置收口（改为真正生效）

- `initPresetsAsync()` 此前全仓库**无任何调用点**：YAML 被打进 npm 包却从不读取，
  用户改配置不产生任何效果，实际生效的只有硬编码常量。
- 在 `cmd_ffmpeg.js` 的 `cmdConvert()` 中、且在 `presets.getPreset(argv.preset)` **之前**调用
  （顺序关键，否则 YAML 新增的预设永远无法被 `--preset` 识别）；加载失败仅告警并回退内置预设。
- 实测：`--show-presets` 从此前的 21 个变为 **23 个**，`hevc_qsv2k`/`hevc_qsv2km` 已可用。
- 附带修正一处不一致：硬编码的 `aac_he`/`aac_voice` 缺少 `-map 0:a`，
  而其余音频预设都有；YAML 版本补齐了它，随本次启用一并纠正。

### P1-2 批处理失败即中断

- `cmd/cmd_move.js` 的 `try` 包住**整个**内层循环：任一文件 `fs.move` 失败，
  当月剩余文件**全部不再处理**，且被笼统计入 skipped，看不出是失败。
  → `try` 下沉到逐文件；`moved/skipped/failed` 三项分别计数并分别上报。
- `cmd/cmd_moveup.js` 汇总口径用 `totalCount`（扫描数）而非实际移动成功数 → 数字虚高，
  改为 `movedCount/totalCount`。
- `cmd/cmd_moveup.js` 的 `cleanupEmptyDirs` **仅凭集合差就整目录移入回收站**，
  未校验目录确实为空：移动失败残留的文件、以及未纳入扫描的非媒体文件
  （`.txt`/`.nfo`/`.db`）会随目录一起被搬走。→ 删除前 `readdir` 确认空，
  非空/不可读的一律保留并列出样本。

### P1-3 解压安全

- **Zip bomb**：条目声明的 `uncompressedSize` 来自包内头部，完全不可信，
  而原先唯一的 2GB 保护已被注释掉。新增「绝对上限 20GB + 压缩比上限 200×」双判据
  （小 zip 至少允许解出 100MB，避免误伤高压缩比文本），超限时中止整个压缩包并清理临时文件。
- `--override` 此前走 `fs.remove` **硬删除**且无二次确认 → 改为 `safeRemove` 移入回收目录
  （误操作可找回）；失败则中止，绝不带着残留继续解压。

### P1-4 `rename` 同批重名检测是死分支

- `cmd/cmd_rename.js` 的 `seenPaths` 全文件**无任何 `.add()`**，`:774` 分支永不成立。
  同批两个源文件映射到同一目标名时，因尚未落盘 `fs.pathExists` 查不到，
  后一个会**覆盖**前一个，且 dry-run 预览与实际执行结果不一致。
  → 在 `outPath` 赋值处补 `seenPaths.add(newPath)`。

### P1-6 `cmd_ffmpeg` 死分支与残留

- `--decode-mode cpu` / H264 10bit 只写入 `useCPUDecode`，而 `createFFmpegArgs` 只读 `useCUDA`
  → 该分支永不生效。改为 `useCPUDecode` 为真时跳过 CUDA 探测直接走软解。
- `if (!useCUDA) tempFilters = "hwupload_cuda," + tempFilters`：无条件前置会给**纯 CPU 滤镜链**
  （`scale=...`）插入无效节点而直接失败 → 仅当滤镜链确实含 `_cuda` 时才上传。
- `srcVideoBitrate = ivideo?.bitrate || fileBitrate - 48*1000 || 0`：码率未知时得到 **-48000**，
  污染 `videoBitScale` → 加 `Math.max(0, ...)`。
- `--delete-source-files` 的判据仅为 `fs.pathExists`：上次 Ctrl+C 中断残留的
  **0 字节/半截文件同样满足**，会导致「源文件已删、产物却是坏的」的不可逆损失。
  → 记录已存在产物的体积，要求 `> 0` 才允许删源，否则保留源文件并单独告警。
- 新增临时产物注册表 + `SIGINT`/`SIGTERM`/`exit` 清理钩子：
  此前只在 `try/finally` 清理，Ctrl+C 时 finally 不执行，`*_tmp@hash@tmp_` 半截文件永久残留。
  （execa 已用 `cleanup: true` 负责杀死子进程，这里只负责文件。）

### P1-8 用户输入校验

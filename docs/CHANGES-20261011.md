## 14:58:02 — 引入跨平台长耗时/大批量任务阻止系统睡眠机制 (Sleep Blocker)

为解决视频转码（FFmpeg）、海量图片压缩、相册精选去重、批量重命名等长耗时批量任务在无人值守时因操作系统自动休眠导致任务中断挂起的问题，引入纯 Node.js 跨平台休眠阻止模块与生命周期管理机制：

### 1. 跨平台纯 Node.js 实现 (`lib/sleep_blocker.js`)
- **零原生编译免依赖**：严禁引入 C++ 原生扩展（node-gyp / node-addon-api），确保 `mediac` 纯 JS CLI 跨平台免编译、秒级安装。
- **Windows 原生适配**：
  - 调用 Win32 官方标准 API `SetThreadExecutionState`（`ES_CONTINUOUS | ES_SYSTEM_REQUIRED = 0x80000001`），普通权限即可运行，无需管理员权限。
  - 通过后台隐藏 PowerShell 子进程（`windowsHide: true`，无弹窗）执行，子进程通过 `[Console]::In.ReadLine()` 读取主进程 `stdin`。
  - **防僵尸/防悬挂联动**：任务正常完成主动关闭 stdin/kill 退出；若主进程异常崩溃或被 Ctrl+C / SIGINT 强杀，操作系统自动切断管道，子进程读取到 EOF 立即自动退出，Windows 自动恢复休眠，绝不泄漏死锁。
  - **仅阻止系统休眠**：不强制常亮屏幕（允许显示器超时正常关屏息屏以节能）。
- **macOS 与 Linux 适配**：
  - macOS：原生调用 `/usr/bin/caffeinate -i -s -w <pid>`，系统内核监控父进程 PID。
  - Linux：优先通过 `systemd-inhibit --what=idle:sleep` 保活；若系统无 systemd，则优雅降级为 no-op，记入 debug 日志，不影响主任务执行。
- **引用计数与异常安全包装**：
  - `acquireSleepLock` / `releaseSleepLock`：内置引用计数，允许多任务重入与嵌套，首次获取启动，全部释放后撤销；`release` 幂等安全。
  - `withSleepLock(taskFn, { reason, enabled })`：RAII 作用域执行高阶函数，`try ... finally` 确保在任何成功、错误或中断下锁必然释放。

### 2. 全局 CLI 参数与配置支持 (`index.js`, `lib/i18n.js`)
- 注册全局命令行选项 `--prevent-sleep`（别名 `--nosleep`，布尔值，默认 `true`）。
- 允许用户传入 `--no-prevent-sleep` 或 `--prevent-sleep false` 显式禁用。
- 环境变量支持：若设置 `MEDIAC_PREVENT_SLEEP=0` 或 `false`，默认禁用休眠阻止。
- 多语言词条支持：在 `lib/i18n.js` 中新增选项说明及激活/释放/失败提示的中英文翻译。

### 3. 大批量与长耗时命令接入
避免在用户等待交互确认时提前占用，统一在用户确认后**真正进入耗时批量执行阶段**时持有锁：
- **`cmd/cmd_ffmpeg.js`**：在 `runFFmpegTasks` 实际转码执行闭包中包裹。
- **`cmd/cmd_compress.js`**：在 `runCompression` 与 `purgeSrcFiles` 图片压缩与清理执行中包裹。
- **`cmd/cmd_pick.js`**：在照片特征分析与 `copyPickedFiles` 复制执行中包裹。
- **`cmd/cmd_dcim.js`**：在实际重命名与文件备份阶段包裹。
- **`cmd/cmd_zipu.js`**：在批量 ZIP 解压执行中包裹。
- **`cmd/cmd_rename.js`**：在实际文件重命名执行中包裹。
- **`cmd/cmd_remove.js`**：在 `runRemoveTasks` 实际删除执行中包裹。

## 14:21:48 — 引入统一事务日志（Journal/Manifest）、rollback 回滚命令及目录持久化规范

为 `rename`、`prefix`、`moveup`、`remove` 等具有文件移动/改名/删除破坏性操作的命令引入详细准确的结构化 JSON 事务日志（Operation Manifest / Journal）以及 `rollback` 回滚子命令，支持故障一键复原与 dry-run 行为标准化。

### 1. 事务日志与回滚系统 (`lib/journal.js`, `cmd/cmd_rollback.js`)
- **`OperationJournal` 核心类**：
  - 统一记录每一笔文件操作：`MOVE`、`RENAME`、`TRASH`、`DELETE`。
  - 记录完整元数据：`timestamp`、`command`、`argv`、`cwd`、`isDryRun`、`stats` 及操作明细数组（包含 `src`、`dest`、`status`、`error` 等）。
  - 实时落盘与进程异常防护：每次记录操作自动更新或在 `finalize` 时刷新；内置 `beforeExit`/`uncaughtException` 兜底保护，确保即使意外中断也能保存最后状态。
  - 操作结束终端自动打印回滚指引及清晰路径提示（如 `mediac rollback <manifest.json>`）。
  - 支持 `copyTo(targetDir)` 自动将日志和 manifest 同步分发至目标输出目录。
- **`mediac rollback` (别名 `undo`, `rb`) 子命令**：
  - 支持传入指定 manifest JSON 文件路径，或默认自动加载最近一次操作的 manifest。
  - 严格采用后进先出（LIFO）逆序执行回滚，保证依赖顺序正确。
  - 内置冲突与安全检测：检查源文件存在性、目标路径是否被外部新文件占用，发生冲突主动告警并跳过。
  - 默认 dry-run 预览，添加 `--doit` 真实执行回滚；回滚自身同样生成新事务日志以便审计。

### 2. 存储位置与目录规范调整 (`lib/debug.js`, `lib/helper.js`)
- **持久化目录迁移**：日志文件（`mediac_log_*.txt`）与 Journal Manifest 文件（`*.json`）根目录由系统临时目录迁移至用户持久化数据目录（Windows 下为 `C:\Users\<user>\AppData\Local\mediac\`，Linux/macOS 为 `~/.local/share/mediac/`），防止被操作系统自动清理。
- **同磁盘安全删除 (`safeRemove`)**：
  - 删除文件由原先统一转移到 `$HOME/.mediac/deleted` 改为转移到**同磁盘文件系统根目录**下的 `.mediac/deleted/`（例如 `C:\.mediac/deleted/` 或 `D:\.mediac/deleted/`）。
  - 保持文件原本完整的目录层级结构，避免同名文件冲突并利于还原与审查。
  - 保留卷根权限不足时的降级安全机制（若卷根不可写，降级转移至用户主目录，杜绝文件损坏或直接丢失）。
- **副本同步分发**：若命令指定了 `output` 目录或触发了删除操作，自动将当前运行的文本日志和 manifest 复制一份至 `output` 目录或 `.mediac/deleted` 目录。

### 3. 命令层改造与 Dry-Run 真实反映
- **`cmd/cmd_moveup.js`**：
  - 接入 `OperationJournal` 记录文件移动。
  - 修复 dry-run 模式下因模拟移动返回 `false` 导致统计被置零的问题，准确输出计划移动文件数、预览样本与统计信息。

  - `renameOneFile` 与 `renameFilesTwoPhase` 全面接入 `OperationJournal`，记录主文件与字幕/附加文件的重命名轨迹。
  - 修复 dry-run 状态下的统计与提示。
- **`cmd/cmd_prefix.js`**：
  - 接入 `OperationJournal`，改善 dry-run 模式下仅有一行警告的体验，输出预览明细与计划改名统计。

  - dry-run 模式输出真实匹配文件样本与大小统计；删除时自动同步 manifest 与日志至 `.mediac/deleted` 目录。

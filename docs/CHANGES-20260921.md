# 变更记录 2026-09-21

## 18:50 Phase 4（T5）：硬件加速自动适配修复（lib/hwaccel.js + lib/hwdetect.js + lib/ffmpeg_run.js）

在 Phase
1-3（YAML 预设单源化、滤镜三段式、显式 encoder/decoder 指定）基础上，修复自动适配层的四处缺陷：

### 1. auto 候选链移除 d3d 层（`lib/hwdetect.js` candidateTiers）

- **变更**：auto 默认链从「厂商专属层 → d3d → cpu」改为「厂商专属层 → cpu」，`caps.usable.d3d`
  不再自动入链。d3d 是「任意厂商 d3d11va 解码 +
  NVENC 编码」的混合层，auto 语义下对多数机器都不是最优解（AMD/Intel 机器上 nvenc 编码器不存在）。
- **显式指定仍可覆盖**：`--hwaccel d3d/d3d11va/d3d12va` 白名单分支与 `--decode-mode gpu`
  不受影响，归一化到 d3d 层后照常使用（白名单层可用 → `[d3d, cpu]`，gpu 模式 →
  `[d3d]`）。逐层探测兜底不变。

### 2. 静态滤镜预筛（`lib/hwdetect.js` candidateTiers 消费 caps.filterSupport）

- **变更**：auto 默认链对厂商层做静态预筛——该层的缩放滤镜必须被当前 ffmpeg 构建支持（cuda→`scale_cuda`、qsv→`scale_qsv`、amf→`vpp_amf`），滤镜缺失则该层不进候选链（warn 记录跳过原因）。此前老构建缺
  `scale_cuda`/`vpp_amf` 时该层总被尝试、probe 必然失败，白白多一次干跑。
- **范围**：仅 auto 默认链；显式白名单 / gpu 模式不预筛（用户明确指定时由探测兜底裁决）。

### 3. codecFamily 扩展 av1/vp9 + ENCODER_MATRIX 补行（`lib/hwaccel.js`）

- `codecFamilyOf`：识别 `/av1|av01/` → `av1`、`/vp9|vp09/` →
  `vp9`（置于 hevc 判定的 hevc/h265/x265/hvc1 之前； `av01`/`vp09`
  是 ffprobe 的短名）。`codecFamilyOfPreset` 随之支持 `--video-codec av1_nvenc`、
  `videoCodecFamily: av1/vp9`。
- `ENCODER_MATRIX` 补行（依据 docs/ffmpeg/ffmpeg-guide-hwaccel-compat.md 的编码器可用性）：
    - cuda/d3d：`av1 → av1_nvenc`（**无 vp9_nvenc**，键缺）
    - qsv：`av1 → av1_qsv`、`vp9 → vp9_qsv`
    - amf：`av1 → av1_amf`（**无 vp9_amf 编码器**，键缺）
    - cpu：`av1 → libaom-av1`、`vp9 → libvpx-vp9`（libsvtav1 不随 ffmpeg 主构建分发，本机实测无；libaom-av1 是随包可用的保守默认，质量优先）
- **矩阵缺失 fallback**：某层缺该族硬件编码器（cuda/vp9、amf/vp9）时 `buildEncoderArgs` 回退
  `ENCODER_MATRIX.cpu`（libvpx-vp9）——编码走 CPU，但解码仍走该层硬件（层只决定解码路径）。

### 4. 探测与真实命令强同源修正（lib/hwaccel.js + lib/ffmpeg_run.js）

- **bitrateK 透传**：`resolveHwPlan` → `selectTier` → `probeLayer` → `buildProbeArgs` →
  `buildLayerArgs` 全程透传 `entry.dstArgs.videoBitrateK`（真实命令带 `-maxrate/-bufsize`
  时探测也带，避免码控参数改变编码行为导致探测结论与真实不一致）。
- **probeCacheKey 补 speed/framerate**：speed≠1 或 framerate 非空时滤镜链含 setpts/fps，缺键会让「带滤镜」与「不带滤镜」的探测结果互相复用而误判。
- **质量参数按实际编码器分发**：`buildEncoderArgs` 由 `tierImpl(tierName)` 改为
  `encoderCalibImpl(encoder)`（按实际编码器名判实现）。此前 cuda/amf 层 vp9 回退 libvpx-vp9 时会错给 nvenc/amf 参数，CPU 编码器不认；现统一按编码器实现走 cpu 分支（-crf）。
- **CPU av1/vp9 纯 CRF 补 `-b:v 0`**：libaom-av1 / libvpx-vp9 必须 `-b:v 0` 才走纯 CRF，否则 `-crf`
  无效（docs/ffmpeg/ffmpeg-guide-encoders.md 11.1「-crf 无效」条目）。

### 相关文件

- `lib/hwaccel.js`：ENCODER_MATRIX、codecFamilyOf、buildEncoderArgs（fallback + 实现分发 + -b:v
  0）、probeCacheKey、probeLayer、selectTier（bitrateK 透传）；删除不再使用的 tierImpl。
- `lib/hwdetect.js`：candidateTiers（d3d 移除 + FILTER_SUPPORT_KEY 静态预筛）。
- `lib/ffmpeg_run.js`：resolveHwPlan 传 `entry.dstArgs.videoBitrateK` 进 selectTier。

## 16:30 新增：ffmpeg --strict 严格模式（探测不支持即跳过该文件，默认关闭保持兼容）

按确认的语义落地严格模式：**prepare/plan 阶段探测到软件或硬件不支持时，warn 日志 + 跳过该文件**，跳过文件**不进入 confirm 重试名单、不会真正走到 run
ffmpeg 阶段**，其余文件继续，EXIT=0；不再自动降级、也不整体报错退出。`--strict`
为布尔开关，**默认 false**（保持既有兼容行为），仅显式传入才启用严格模式。

### 严格模式各探测路径

- **H264 10bit**（`cmd/cmd_ffmpeg.js` prepare）：Nvidia/Intel 均无 10bit H264 硬解，strict 下
  `Skip[Strict10bit]` + warn + 跳过（不再静默切软解）。
- **音频编码器缺失**（`cmd/cmd_ffmpeg.js`
  prepare 预检）：预设指定了本机构建不支持的编码器（如缺 libfdk_aac 的版本用到 `-c:a libfdk_aac`）→
  `Skip[StrictCodec]` + 跳过，失败在 prepare 拦截、不拖到 confirm/run 阶段。
- **硬件层不可用**（`lib/hwaccel.js` selectTier + `lib/ffmpeg_run.js`
  run 阶段 catch）：strict 下只尝试第一候选硬件层，失败即 `Skip[Strict]` +
  `entry.skipped = true`（不设
  `ffmpegFailed`，自动不进 confirm 重试名单、不真正执行 ffmpeg）；候选链全为 cpu 时同样抛错，提示用
  `--decode-mode cpu` 显式指定软解。
- **run 阶段 CPU 降级重试**（`cmd/cmd_ffmpeg.js`
  runFFmpegTasks）：strict 下失败不再询问 CPU 重试，warn `ffmpeg.strict.retry` 后跳过。

### 汇总与日志

- `runFFmpegTasks` 结果汇总加入 `skipped=` 计数（含无跳过时不输出，保证日志兼容）；逐文件落盘
  `Skip[Strict] <path> 原因`。
- `lib/i18n.js`：新增 `ffmpeg.strict` / `.strict.hw` / `.strict.audio` / `.strict.retry` /
  `.strict.10bit` / `.strict.skip.count` 中英文案，strict 语义文案统一为「跳过该文件」。

## 16:10 新增：FFmpeg 二进制定位统一（lib/ffmpeg_bin.js）+ 能力探测去重

同一批改动顺带解决「探测与执行用的不是同一个 ffmpeg」的不一致问题：

- **`lib/ffmpeg_bin.js`（新建）`resolveFFmpegBinary()`**：定位优先级 `FFMPEG_PATH` → `FFMPEG_BINARY`
  →
  `which("ffmpeg")`，环境变量指向的文件**实际存在**才采用，否则继续往下找；解决「PATH 里无 fdk 的版本排在 nonfree 版之前」导致探测/执行结果不一致的问题。
- **`lib/ffmpeg_run.js`** `executeFFmpeg` 改执行 `ffmpegPath || "ffmpeg"`（探测与执行同一二进制）。
- **`lib/hwdetect.js`**：in-flight promise 去重（prepare 阶段多任务并发预检时只实际探测一次）；新增
  `parseVersionInfo` 解析 `ffmpeg -version` 的版本与 configuration 串，随探测打印环境信息。
- **`lib/ffmpeg_build.js`** `buildAudioArgs` 接入 caps：非 strict 下音频编码器不可用时**静态降级**
  `libfdk_aac → aac`（预览命令结构即与真实执行一致）；strict 下 `fallbackAudioEncoder`
  不降级原样返回（拦截职责在 prepare 预检）。导出 `fallbackAudioEncoder` 纯函数。

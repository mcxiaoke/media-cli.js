# CHANGES-20260926

## 2026-09-26 10:07 — ffmpeg 全链路评审问题修复（CLI + Electron + UI/UX）

依据 `docs/FFMPEG-REVIEW-20260926.md` 的评审结论，按「最小改动、不引入新行为」原则修复。

### 一、功能正确性（用户可感）

- **`--hwaccel cpu` 真正生效**（`src/transcode/hwdetect.js`）：`candidateTiers` 此前把 `cpu` 静默穿透到默认候选链，实测 `auto + hwaccel=cpu` 返回 `[cuda,swdec,d3d,cpu]`，与 `auto` 完全一致。现在 `cpu` 直接返回 `["cpu"]`（与 `--decode-mode cpu` 同义），CLI 与桌面端「硬件加速方式=cpu」不再是假开关。
- **桌面端「实时速度 / 剩余时间」恢复显示**（`src/transcode/ffmpeg_run.js`、`stores/plan.ts`）：`ffmpeg -progress` 的 `speed` 是 `"1.5x"` 字符串，而 store 用 `typeof === "number"` 判定，导致 `currentSpeed` 恒为 0、两个指标恒显示 `—`。现由执行层输出数值 `speed`（另附 `speedText`），store 侧同时接受数字/字符串以防御回归。
- **AMD 显卡不再丢失 AMF 硬编**（`src/transcode/gpu.js`、`hwdetect.js`）：`normalizeVendor` 新增 `radeon` 匹配（Windows 返回 `AMD Radeon ...` 型号串），`primaryVendor` 在 GPU 列表归一化为 `other` 时回退到设备探测得出的 `caps.vendor`。实测候选链由 `[d3d,cpu]` 恢复为 `[amf,swdec,d3d,cpu]`。
- **桌面端「移除所选」补齐状态同步**（`TaskTable.vue`）：底栏按钮此前只改 `planStore`，现与右键菜单共用同一实现，同步 `configStore.inputs` 与主进程 `stagedEntries`，并加 `isPlanBusy()` 守卫。
- **About 弹窗版本号改为真实值**（`AboutModal.vue`）：原先硬编码 `v0.1.0`，`envStore.version` 全渲染层无消费点。

### 二、状态语义

- **用户层预设可跨层 `extends` 内置预设**（`preset_loader.js`）：`resolveExtends` 增加 `base` 查找域，`loadPresetLayers` 逐层累积 base。此前 `extends: hevc_2k` 会 `Preset not found` 并整条丢弃。
- **运行期修改配置不再被静默吞掉**（`stores/plan.ts`、`App.vue`）：`markStale()` 在 RUNNING/PLANNING/STOPPING 时改为置 `pendingStale`，会话收敛时由 `applyPendingStale()` 兑现为 STALE；`startExecution` 的重推演条件纳入 `pendingStale`，消除「界面配置已改、实际执行旧 argv」的不一致。
- **重试时被重建判定为跳过的任务不再误标成功**（`ffmpeg_engine.js`）：`prepareAttempt` 合并后若 `status === "skipped"`，立即以 skipped 收尾并停止本任务（此前继续执行 ffmpeg，成功后又被 `toRunResult` 优先读成 skipped，统计与 UI 双错）。

### 三、文档与实现对齐

- **移除幽灵选项**：`--video-args` / `--audio-args` / `--filters` / `--filter-complex` 已在提交 `0b03adb` 中删除，但 README.md、README_zh.md、`docs/ffmpeg/FFMPEG-USAGE.md`、`presets.example.yaml`、`lib/i18n.js` 仍把它们当正式能力描述（实测 CLI 报 `Unknown arguments`）。本次统一改为「已移除 + 改用预设字段」的准确表述。
- 删除 5 个无消费者的 i18n 死键（`ffmpeg.video.args` / `ffmpeg.audio.args` / `ffmpeg.filters` / `ffmpeg.error.videoArgsCodec` / `ffmpeg.warn.encoderSpecific`）。
- 删除 `OPTION_KEYS` 中 4 个已无消费者的键（`filters` / `filterComplex` / `videoArgs` / `audioArgs`）及 `ffmpeg_build.js` 中读取 `audioArgs` 的 3 处死分支。
- 修正 6 处与实现矛盾的注释（`ffmpeg_build.js` ×3、`hwaccel.js` ×3、`ffmpeg_run.js` ×2、`ffmpeg_presets.js` ×2）。

### 四、工程健壮性与 UI/UX

- **库不再劫持宿主进程信号**（`ffmpeg_run.js`）：`SIGINT/SIGTERM` 处理（含 `process.exit(130)`）只在非 Electron 环境注册，避免库代码决定 GUI 退出。
- **`toSerializable` 改用路径栈**（`ipc-serializer.ts`）：共享 WeakSet 会把 DAG（同一对象被两字段引用）误判为 `[Circular]`；Set/Map 也纳入进出栈，消除自引用集合的无限递归。
- **探测缓存键纳入 `quality`**（`hwaccel.js`）：长驻进程跨批次换 `--video-quality` 不再复用旧结论；`bitrate/maxBitrate` 有意不入键（逐文件缩放值会让每文件成为独立键、缓存彻底失效，且码率不改变「该层能否打开文件」）。
- **`--error-file` 支持显式路径**（`ffmpeg_run.js`）：非 `json`/`text` 的取值视为文件路径（相对路径基于输出目录），多文件共用时追加而非覆盖；修复 JSON 模式下 `JSON.stringify(Error)` 得 `{}` 导致 message 丢失。
- **运行中禁止 reload**（`main/index.ts`）：`role: "reload"/"forceReload"` 改为带 `guardReload()` 的显式菜单项，避免渲染层重建后与引擎脱钩（进度丢失、无法终止）。
- **mediainfo 死控件接线**（`lib/mediainfo.js`、`ffmpeg-environment.ts`、`ffmpeg-service.ts`、`contracts.ts`、`App.vue`、`AboutModal.vue`）：设置里的 mediainfo 路径此前只被渲染层收集与持久化，主进程完全不消费；现作为 ffprobe 失败时的兜底探测工具真正传入。
- **输出目录一致性**（`ConfigPanel.vue`、`App.vue`、`ExecutionBoard.vue`）：目录选择器与手动输入统一走 `setCustomOutputDir`（修复 `savedCustomOutputDir` / `outputBesideSource` 不同步）；`openPath` 增加 catch 与日志，白名单拒绝不再静默。
- **推演命令诚实标注**（`TaskInspectorDrawer.vue`、`TaskTable.vue`、`stores/plan.ts`）：命令来源区分「计划推演 / 本地估算」并在估算时给出警示；替换基准由 `tasks[0]` 改为按 path 反查（`previewCmdFor`），修复移除过首行后复制出错误命令。
- **UI 细节**：FAILED 状态也显示「打开输出目录」；状态胶囊在 RUNNING/PLANNING/STOPPING 不再被「待规划」覆盖；设置面板开关补 Space/Enter 键盘激活；右键菜单支持 Shift+F10 / ContextMenu 呼出与键盘激活；并发数上限与文案对齐主进程真实行为（1–8，视频并非强制串行）。
